# ساخت نسخهٔ بومی آزمایشی CTR360 برای Xbox 360

این پوشه فعلاً یک **آزمون بوت متنی** است؛ هنوز بازی سه‌بعدی نیست. برای ساخت فایل `ctr360_boot_test.elf32` باید LibXenon/Xenon Toolchain روی یک محیط Linux نصب باشد.

## بررسی و ساخت خودکار
از ترمینال Linux در همین پوشه اجرا کن:

```bash
./build.sh
```

این اسکریپت وجود `DEVKITXENON`، فایل `rules` و کامپایلر `xenon-gcc` را بررسی می‌کند و اگر همه حاضر باشند، `make` را اجرا می‌کند. اگر ابزارها حاضر نباشند، دلیل دقیق را چاپ می‌کند.

## نصب ابزار ساخت
راهنمای رسمی و دستورهای به‌روز: https://github.com/Free60Project/libxenon
مستندات رسمی می‌گوید ابزار ساخت و کتابخانه باید روی Linux نصب شوند؛ این فرایند به دانلود منابع و ابزارهای توسعه نیاز دارد. پس از نصب معمولاً مسیر پیش‌فرض چنین است:

```bash
export DEVKITXENON="/usr/local/xenon"
export PATH="$PATH:$DEVKITXENON/bin:$DEVKITXENON/usr/bin"
```

سپس دوباره `./build.sh` را اجرا کن.

## اجرای فایل در XeLL
فقط پس از اینکه فایل `.elf32` واقعاً ساخته شد: آن را به ریشهٔ USB با فرمت FAT32 کپی کن و نامش را `xenon.elf` بگذار تا XeLL Reloaded آن را اجرا کند. این روش را پیش از ساخت فایل واقعی نمی‌توان آزمایش‌شده دانست. به NAND یا داشبورد کنسول دست نزن.

## بررسی وضعیت ساخت
برای گزارش روشن از ابزارهای موجود، این دستور را اجرا کن:

```bash
./diagnose.sh
```

این بررسی فقط ابزارها را تشخیص می‌دهد و خودش فایل اجرایی تولید نمی‌کند.

## وضعیت این محیط
در محیط فعلی پروژه، `DEVKITXENON`، فایل `rules` و `xenon-gcc` وجود ندارند و دسترسی شبکهٔ محیط ترمینال نیز برای دریافت ابزارها در دسترس نیست. بنابراین این اسکریپت آماده شده، اما فایل اجرایی Xbox 360 هنوز ساخته نشده است.

## مسیر جایگزین برای ساخت (Docker / GitHub Actions)

در این محیط فعلی Docker و ابزار `xenon-gcc` موجود نیست و دسترسی شبکه هم برای دریافت ابزارها برقرار نیست؛ بنابراین اینجا نمی‌توانم واقعاً فایل ELF را کامپایل کنم. برای اینکه مسیر ساخت آماده باشد، دو مورد اضافه شده است:

- `build_in_docker.sh`: روی یک سیستم Linux/macOS که Docker روی آن نصب و فعال است اجرا می‌شود و از تصویر `free60/libxenon:latest` استفاده می‌کند.
- `.github/workflows/build-xbox360.yml`: اگر پروژه در یک مخزن GitHub قرار بگیرد، از بخش Actions می‌توان workflow را دستی اجرا کرد؛ فایل خروجی به‌عنوان Artifact بارگذاری می‌شود.

این موارد فقط مسیر ساخت را خودکار می‌کنند؛ تا زمانی که workflow واقعاً اجرا و Artifact تولید نشده باشد، ادعا نمی‌کنیم که فایل اجرایی ساخته شده است. همچنین این ELF فعلی صرفاً برنامهٔ بوت متنی است؛ حتی اگر کامپایل شود، هنوز خود بازی مسابقه‌ای نیست. راهنمای رسمی تصویر Docker و دستور ساخت در مستندات LibXenon آمده است.
