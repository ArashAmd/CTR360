# ساخت آزمایشی بومی Xbox 360 از طریق GitHub Actions

این مسیر از تصویر Docker رسمی پروژهٔ LibXenon یعنی `free60/libxenon:latest` استفاده می‌کند. پروژه را باید در مخزن GitHub خودتان بارگذاری کنید؛ من از این گفت‌وگو به حساب GitHub شما دسترسی ندارم و نمی‌توانم workflow را به‌جای شما اجرا کنم.

## مراحل

1. فایل ZIP پروژه را دریافت و از حالت فشرده خارج کنید.
2. **تمام محتویات** پوشه را به مخزن GitHub جدید بارگذاری کنید؛ پوشهٔ مخفی `.github/workflows` باید در مخزن باشد.
3. مخزن را باز کنید و وارد **Actions** شوید.
4. workflow با نام **Build CTR360 Xbox 360 boot test** را انتخاب و روی **Run workflow** بزنید.
5. اگر موفق شد، از بخش **Artifacts** فایل `ctr360-xbox360-boot-test-elf32` را دریافت کنید.
6. اگر شکست خورد، Artifact با نام `ctr360-xbox360-build-log` را دریافت و متن خطا را برای من بفرستید. این گزارش کمک می‌کند خطای واقعی را برطرف کنیم.

## چه چیزی ساخته می‌شود؟

این workflow فقط `native/source/main.c` را می‌سازد؛ این برنامه فعلاً یک آزمون بوت متنی و کنترلر است، **نه بازی مسابقه‌ای سه‌بعدی**. خروجی مورد انتظار `native/ctr360_boot_test.elf32` است.

- workflow هنوز تا وقتی واقعاً در مخزن شما اجرا نشود، تأییدشده نیست.
- ELF را با XEX اشتباه نگیرید. روش اجرای ELF به محیط homebrew/XeLL و سازگاری آن بستگی دارد.
- برای این آزمایش NAND یا داشبورد کنسول را تغییر ندهید.
- این روش به GitHub Actions و دریافت تصویر Docker از اینترنت نیاز دارد.
